# Quran Android Interface Craft

صمّم واجهة تطبيق وِرد بوصفها أداة قراءة وتسميع يومية، لا شاشة إعدادات تقنية. حافظ على الصدق المنتجِي: لا تخفِ اعتماد Online على الشبكة، ولا تعرض نجاحاً قبل جاهزية الأصول أو النموذج. اجعل العربية وRTL والقراءة الطويلة ومحاذاة الكلمات أولويات التصميم.

## موجز التصميم

حدّد قبل الكود:

| المحور | القرار الافتراضي لهذا النظام |
|---|---|
| الجمهور | حافظ أو متعلم يريد قراءة صفحة قصيرة وتسميعها يومياً |
| المهمة الأساسية | اختيار السورة، إخفاء النص، بدء التسميع، معرفة الكلمة الحالية والمشكلة |
| النبرة | هادئة، قرآنية، واضحة، بلا زخرفة تنافس النص |
| التوقيع البصري | أخضر زمردي داكن للتقدم، ذهبي هادئ للأفعال الأساسية، وبطاقات واسعة ذات حواف لطيفة |
| الأولوية | النص/الكلمة الحالية ثم حالة المحرك ثم مصدر الأصول ثم الهدف والسجل |

استخدم نظام ألوان محدوداً: `QuranGreen`, `QuranGreenDark`, `QuranGold`, `QuranSurface`, `QuranBackground`, و`QuranMuted`. استخدم دوراً طباعياً للنص القرآني الكبير ودوراً واضحاً للشرح والأزرار. اجعل المقاسات قابلة للقراءة على شاشة 720×1600، ولا تعتمد على قص النص أو ترتيب لاتيني داخل جمل عربية.

## بنية الشاشة

قسّم شاشة التسميع إلى مناطق مستقلة:

1. رأس يعرّف وِرد وحالة المحرك الحالية.
2. اختيار السورة والصفحة.
3. بطاقة محرك التسميع، Online أو Offline، مع حالة النموذج.
4. بطاقة مصدر الأصول، Stream أو Download/Local، مع حالة التنزيل.
5. بطاقة الهدف اليومي.
6. بطاقة المصحف، مع زر واضح لإخفاء النص.
7. عند الإخفاء والتسميع، اعرض الكلمة الحالية التي التقطها الجهاز في بطاقة بارزة، واعرض موضعها داخل سلسلة النقاط إن أمكن.
8. بطاقة التسميع الداكنة، بعبارة حالة صادقة وزر واحد أساسي يبدأ أو يوقف الجلسة.
9. إشعار قابل للفهم، ثم السجل في تبويب مستقل.

لا تجعل شريط التبويب السفلي يبدو كزر بدء التسميع. ميّز بين تبويب «التسميع» وبين زر «ابدأ التسميع» داخل بطاقة الجلسة بلون وموضع ونص مختلفين.

## حالات الواجهة

صمّم وأثبت الحالات الآتية: بداية التحميل، جاهزية النص، تعذر الأصول مع إعادة المحاولة، اختيار Online، اختيار Offline والنموذج غير موجود، تنزيل النموذج، النموذج جاهز، Stream، Download، تنزيل السورة، الإخفاء قبل الجلسة، الاستماع، توقف مؤقت طبيعي، نتيجة جزئية، نتيجة نهائية، كلمة مفقودة، كلمة زائدة، توقف يدوي، وسجل فارغ. اربط كل حالة بـViewModel حقيقي؛ لا تستخدم loading ثابتاً أو نجاحاً وهمياً.

## الإخفاء والكلمة الحالية

عند إخفاء النص، استبدل كل كلمة بنقطة أو رمز موحد، ولا تعرض النص الكامل. أثناء الجلسة، اعرض آخر كلمة التقطها recognizer في بطاقة «الكلمة التي التقطها الجهاز»، وميّز أنها نتيجة جزئية أو نهائية إن كانت الحالة متاحة. لو كانت المحاذاة تعرف موضعها المتوقع، لوّن موضع الكلمة الحالية فقط. عند توقف قصير لا تمسح الكلمة الحالية أو تنهي الجلسة.

## التفاعل والوصول

استخدم أزرار Compose الحقيقية، واجعل مساحة اللمس لا تقل عن 48dp، والعناوين والرسائل مفهومة بالعربية. تأكد من RTL، التباين، القراءة من أعلى إلى أسفل، وعدم تداخل شريط التبويب مع آخر بطاقة. لا تعتمد على UI Automator لاكتشاف عناصر Compose إن لم تُصدّر semantics؛ اختبر التفاعل اليدوي أو إحداثيات مدروسة مع لقطة شاشة، ثم أضف semantics مناسبة عند الحاجة.

لا تستخدم حركة تلقائية أو carousel للمصحف. احترم إعدادات تقليل الحركة، ولا تمنع الضغط أثناء التحميل. عند خطأ الشبكة أعطِ إجراء إعادة محاولة واضحاً، وعند رفض الميكروفون أعطِ مساراً إلى إعدادات الصلاحية.

## مراجعة وإصدار

راجع لقطة البداية، الحالة المخفية، Online listening، الصمت، التخطي، الكلمة الحالية، Offline model ready، وDownload/Local على شاشة الهاتف. افحص القصّ، اتجاه النص، حجم الخط، الأزرار، التباين، وظهور الرسائل. نفّذ build وlint والاختبارات، ثم ثبّت APK عبر ADB والتقط الصور بالترقيم أعلاه. اذكر ما لم يُختبر، ولا تعدّل نسخة Offline المرجعية أثناء تحسين Online.
