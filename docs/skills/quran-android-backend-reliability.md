# Quran Android Reliability

عامل كل عملية ظاهرة للمستخدم بوصفها انتقال حالة صريحاً، وكل أصل بعيد أو نموذج محلي بوصفه اعتماداً قد يفشل. طبّق المهارة على طبقات Android Native، لا على خادم ويب فقط. لا تدّع نجاحاً اعتماداً على شاشة متفائلة؛ أثبت الانتقال بالنص، والملف، والسجل، أو الحالة المرئية.

## عقد الحالة

عرّف حالات `loading`, `ready`, `unavailable`, `downloading`, `downloaded`, `listening`, `paused-by-silence`, `stopped`, `failed`, و`retryable`. افصل هذه الحدود:

| المكوّن | المسؤولية والضمان |
|---|---|
| `RemoteAssetManager` | روابط HTTPS المسموح بها، timeout، تنزيل النص والتوقيتات والصوت والنموذج، تحقق الملف، وعدم اعتبار بدء التنزيل نجاحاً |
| `QuranRepository` | تحليل النص الموثوق وحساب السورة والآيات دون اختلاق بيانات عند فشل التحميل |
| `OnlineSpeechSession` | إدارة SpeechRecognizer، تجميع النتائج الجزئية والنهائية، وإعادة التشغيل بعد الصمت القصير دون إنهاء الجلسة |
| `LocalRecitationSession` | AudioRecord وsherpa-onnx، تحرير الموارد، واستمرار الالتقاط حتى الإيقاف اليدوي أو خطأ حقيقي |
| `QuranViewModel` | مصدر الحالة الوحيد، منع جلسات متزامنة، وإظهار رسالة قابلة للتصرف |
| Compose UI | عرض الحالة الفعلية، تعطيل الإجراء أثناء التنزيل، وعدم إعلان نجاح غير مؤكد |

## الأصول والتنزيل

استخدم قائمة سماح ثابتة للمضيف والمسارات. أعطِ كل طلب بعيد مهلة محدودة ورسالة خطأ آمنة. أعد المحاولة فقط للأخطاء العابرة وبعدد محدود، واجعل تنزيل السورة والنموذج قابلاً لإعادة التشغيل دون تكرار ملف مكتمل. احفظ أصول Download في `filesDir`، ولا تنشئ ملفات صوت في وضع Stream. افصل cache النص والتوقيت عن صوت السورة وعن نموذج FastConformer.

لا تضع روابط خاصة أو أسراراً في APK. لا تضع القرآن الكامل أو الصوت أو النموذج في Online APK. تعامل مع GitHub العام كاعتماد خارجي قد يتأخر أو ينقطع، وأظهر بديلاً صادقاً بدلاً من بيانات وهمية.

## التعرف الصوتي

لـSpeechRecognizer، ميّز بين `partial` و`final`. لا تعلن نهاية الجلسة عند `onEndOfSpeech`، أو `ERROR_SPEECH_TIMEOUT`، أو `ERROR_NO_MATCH`؛ هذه نهاية مقطع وليست نهاية جلسة. أعد تشغيل مقطع الاستماع ما دام المستخدم لم يضغط إيقافاً، واجعل زر الإيقاف يلغي callbacks والموارد. امنع الاستدعاء بعد `destroy`، وسجّل رمز الخطأ دون صوت المستخدم أو بيانات شخصية.

لـFastConformer، تحقق من وجود كل ملفات النموذج قبل إنشاء recognizer، وحرّر AudioRecord وstream وrecognizer في النجاح والفشل والإيقاف. لا تستخدم الشبكة للتعرف المحلي بعد تجهيز النموذج. سجّل زمن التهيئة وفشل الموارد فقط عند الحاجة، ولا تسجل PCM أو التسجيل الخام.

## مطابقة النص

لا تقارن الكلمة المرصودة بالكلمة المتوقعة في الفهرس نفسه فقط. استخدم محاذاة تسلسلية تسمح بعمليات match وmissing وunexpected وuncertain، حتى لا تُحسب الكلمة التالية صحيحة في موضع الكلمة المتخطاة. اعتبر نهاية النتيجة الجزئية غير مؤكدة، واعتبر الحذف بين كلمتين مرصودتين مفقوداً. التقييم تعليمي نصي ولا يحكم التجويد.

## UI والخصوصية

أظهر للمستخدم مصدر الأصول ومحرك التعرف الحاليين. قل صراحة إن Online قد يستخدم مزود النظام/الشبكة، وإن Offline يعالج الصوت محلياً بعد تنزيل النموذج. عند إخفاء النص، لا تعرض النص الكامل؛ اعرض الكلمة الحالية التي التقطها recognizer فقط مع تمييز بصري وحالة جزئية/نهائية واضحة.

## التحقق الواقعي

نفّذ اختبارات الوحدة ثم البناء ثم التثبيت عبر ADB. على الهاتف تحقّق من `adb devices -l`، الصلاحيات، بدء وإيقاف Online، الصمت، التخطي، الإخفاء، Download/Local، وتنزيل نموذج Offline. التقط screenshot بعد كل انتقال مهم، وسجّل logcat من دون أسرار. افصل بين اختبار APK على الجهاز وبين اختبار inference الفعلي للنموذج؛ إن لم يُنفّذ الأخير فوسمه `deferred`.

## مصفوفة الفشل

| الفشل | الحالة المرئية الصحيحة | الإجراء |
|---|---|---|
| تعذر GitHub | `unavailable` مع رسالة | إعادة المحاولة أو التحويل إلى المصدر المحلي الموجود |
| تنزيل جزئي | `downloading` أو `failed` | الاحتفاظ بالمكتمل وإعادة المحاولة دون تلف |
| صمت قصير | `listening` مستمر | إعادة فتح مقطع التعرف |
| لا توجد نتيجة | جلسة مستمرة أو رسالة مؤقتة | لا تُنهي الجلسة تلقائياً |
| ملف نموذج ناقص | `model unavailable` | حذف/إعادة تنزيل النموذج، لا تشغيل recognizer ناقص |
| رفض الميكروفون | رسالة صلاحية قابلة للتصرف | فتح إعدادات الصلاحية أو طلبها مجدداً |
| إيقاف يدوي | `stopped` وتحرير الموارد | منع callbacks اللاحقة |

## مخرجات التسليم

سلّم عقد الحالات، قائمة مصادر الأصول، سجل الأخطاء المنقح، اختبارات الوحدة، أوامر ADB، screenshots مسماة، مصفوفة الرحلة، وما بقي `deferred`. لا تسجل أو تسلم الصوت الخام للمستخدم، ولا تعتبر رسالة نجاح التثبيت دليلاً على نجاح كل ميزات التطبيق.
