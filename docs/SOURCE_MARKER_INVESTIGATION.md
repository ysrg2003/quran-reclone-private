# فحص رموز المصدر

تمت قراءة SQL المرجعي في `tarteel-android-offline/sources/quran.com-images` قراءة فقط، دون تعديل المستودع offline. يحتوي المصدر على أنواع glyph هي `word` و`end` و`pause` و`hizb` و`juz` و`sura` و`bismillah` وغيرها، كما تربط جداول `glyph_page_line` و`glyph_ayah` كل glyph بالصفحة والسطر والموضع والآية.

| الفئة | ما ثبت من المصدر |
|---|---|
| `end` | علامات نهاية الآيات مرتبطة بموضع الآية، ويمكن تمثيلها مع رقم الآية الحالي |
| `pause` | 1,308 glyph موضوعة داخل الأسطر، لكن شكل العلامة مشفر في خط QCF الخاص بالصفحة وليس كحقل Unicode وصفي في SQL |
| `hizb` | 55 موضعاً مرتبطة ببداية حدود الحزب/الربع |
| `juz` | مواضع حدود الأجزاء موجودة في glyph والـmetadata الهيكلية |
| `sajdah` | السجدات موجودة موضعياً في XML metadata وعددها 15؛ لا يظهر لها glyph مستقل في العينة الحالية |
| إطار الصفحة | توجد glyphs من نوع `header-box` و`side-box-half` و`side-box-full`، لكنها تعتمد على هندسة الصورة/الخط وليست إحداثيات إطار عامة في الملف الحالي |

نص `quran_content.json` لا يحتوي مجموعة كاملة من علامات الوقف؛ لذلك لا يجوز تحويل كل `pause` إلى رمز Unicode واحد أو اختراع مواضع `صل` و`قل` و`ج`. التطبيق يمكنه عرض العلامات الهيكلية التي يثبتها metadata، بينما التطابق البصري الكامل لعلامة الوقف يتطلب mapping موثوقاً من glyph/font أو metadata مستقلة. لا تُضمّن خطوط QCF أو صور الصفحات داخل APK.
